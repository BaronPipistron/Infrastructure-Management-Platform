## Узкие места

- Reconcile throughput ограничивается worker pool и queue capacity (`queue_capacity=100`), saturation виден уже на burst-нагрузке.
- Convergence latency заметно зависит от времени reconcile + цикла Inventory sync.
- Detection cycle для больших N в steady-state растет преимущественно через fetch-стадии.

## Рекомендации

1. Добавить явные Prometheus-метрики по стадиям detection cycle (fetch/compare/dispatch) и queue depth Reconciler.
2. Добавить endpoint статуса очереди Reconciler (depth, active_workers, completed/failed counters) для более точных throughput benchmark.
3. Для более реалистичных stress-run добавить профиль с несколькими реальными managed-host контейнерами (например 10-20) как отдельный режим harness.
4. Для convergence benchmark добавить явный event в Inventory о моменте восстановления workload, чтобы уменьшить зависимость от polling.

## Ограничения и допущения

- `100/500` хостов — логическое масштабирование через aliases, а не 100/500 независимых DIND-хостов.
- Стенд локальный, shared-resources (CPU/RAM/Docker daemon) влияют на абсолютные значения метрик.
- Stage timing `drift compare` в steady-state может округляться к `0 ms` на очень быстрых циклах.
